## Wording findings

- `AppUpdate.razor` repeated “Version <version> is available” below the update dialog heading and repeated “Saved music and profiles are kept” in both install variants.
- `ServerStats.razor` and `static/app.js` repeated visible recovery labels in “Retry to load server work” and “Use Retry playback”. `Music.razor` described the queue icon beside an empty queue.
- `Music.razor` and `static/playlists.js` displayed raw operation detail in some paths. The message boundaries now use customer-facing recovery wording when technical exception or HTTP status text reaches the UI.
- `HomeView.razor` used bare “The album could not finish saving. Try again.” with no visual distinction from save progress. `SongPlaylistPicker.razor` used “No playlists found.” for both a filter miss and an empty editable list.
- The compact update label, track chips, progress meters, device presence, and actionable listening invites already communicate state through their existing control or layout. The inventory includes them to make those paths traceable.
