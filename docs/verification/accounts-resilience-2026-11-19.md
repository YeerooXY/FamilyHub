# Accounts, settings and resilience · 19 November 2026

Base revision was FamilyHub 0.1.71. The test used a temporary workspace, two family profiles, a generated JPEG and two generated WAVs. The password-mode fixture used a local Navidrome stub. Both fixtures ran `python -m music_web` behind loopback TLS. The hidden Windows shell used separate storage and trusted only the fixture certificate for the loopback test address. Playwright and the fixture processes ran in the background at idle priority.

| Scenario | Result |
| --- | --- |
| First launch and server entry | Windows accepted HTTPS with a trailing slash and rejected HTTP. A refused HTTPS address now explains how to recover. A failed address change preserved the current song and queue. The client regression also exercises an unrelated server returning HTML. |
| Sign-in and sign-out | Wrong password, correct password, sign-out and sign-in after expiry passed at 1280 px and 390 px. Family profile switching passed in the browser and Windows shell. |
| Profile images and stale sessions | Windows saved a fixture JPEG and retried a stalled upload. The browser chooser now renders the saved image. Switching profiles in a second tab invalidated the old form. The new reload link led to a fresh page and the user could switch profiles. Windows recovered from both 401 and a stale CSRF rejection during Clear listening history and asked the user to retry. A stalled clear request timed out and left the dialog usable. |
| Server restart and offline playback | An open browser tab refreshed the library after a real server restart and retained the family profile. Windows cold-started with the server stopped, restored two cached songs and their saved position, and played, paused and advanced with the keyboard. The separate two-browser handoff test passed including return handoff and queue advance. |
| Updates | Windows showed the newer version and handled a missing package with a retry message. Escape and Later both dismissed the dialog. Later left the update available in the header. Component tests rendered the Windows, Android APK and iOS SideStore actions. |
| Settings and layout | Windows changed Wi-Fi and mobile streaming quality, download quality, Wi-Fi-only downloads, crossfade and theme. Playback and storage values survived a profile round trip. Theme, crossfade and streaming quality also survived a shell restart. Browser crossfade survived reload. The 850 × 640 Windows viewport and 390 px phone portrait/landscape layouts had no horizontal overflow. |
| Keyboard, touch and motion | Tab, Shift+Tab, Enter, Space and Escape passed in the browser profile and Connect flows. Connect preserves focus if the user has already moved to another control. The Android Chrome profile also dismissed Connect with a downward touch drag. The Windows update dialog and listening-history dialog restored focus. The phone-size native player sheet restored focus after Escape, disabled its entrance animation in reduced motion and displayed one label for Report song. |
| Server work and Admin | Empty review and Artist mappings displayed specific messages. A stalled statistics response and 503 review and Artist mappings responses ended with usable retries. Server work reconnected after a 401 and could also reconnect from its own Refresh button while offline in the component fixture. |
| Empty Leaderboard and Wrapped | Zero-play profiles stay out of the rankings and chart. Online profiles still appear under Who's here. Both empty states give the next action. |

Browser checks used Windows Chromium, desktop WebKit, Android-profile Chromium and iPhone-profile WebKit. The Mac and phone results are emulations. Android APK installation, SideStore launch and installation, Windows installation/restart, physical network transitions, physical device rotation and assistive-technology behavior remain unverified. The separate player-bar visual test stopped at its existing violet-versus-green pixel expectation. The account and player-sheet interaction checks completed independently.

The browser regression is `tests/music_account_recovery.cjs`. Point `FAMILYHUB_TEST_ORIGIN` at the isolated TLS family fixture with profiles `sample-a` and `sample-b` and an empty library. Set `FAMILYHUB_TEST_PROFILE_IMAGE` to a JPEG path and optionally `FAMILYHUB_TEST_CAPTURES` to a capture directory. Portable client and rendered component regressions run in `clients/FamilyHub.Client.Core.Tests` and `clients/FamilyHub.ServerWork.Tests`.

Verification passed 88 Python tests, 918 portable client checks, the rendered component suite and the two-browser handoff suite. Local screenshots and native fixture scripts are in `.local/flows3/`.
